# 도메인 모델 — 포인트 원장

## 1. 원칙

1. **원장(ledger)은 append-only.** 수정·삭제하지 않고 반대 거래(취소/환불)로 상쇄한다.
2. **잔액(wallet)은 원장의 파생값.** 동일 트랜잭션에서 원장 INSERT + 잔액 UPDATE.
3. **모든 쓰기는 멱등키를 가진다.** 같은 요청이 두 번 와도 한 번만 반영된다.

## 2. 테이블

```sql
CREATE TABLE point.point_wallet (
  user_id      BIGINT PRIMARY KEY,
  balance      BIGINT NOT NULL CHECK (balance >= 0),
  version      BIGINT NOT NULL DEFAULT 0,        -- 낙관적 락
  updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE point.point_ledger (
  id               BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id          BIGINT NOT NULL,
  type             VARCHAR(20) NOT NULL,          -- EARN, USE, REFUND, EXPIRE, CANCEL
  amount           BIGINT NOT NULL,               -- 부호 포함 (+적립 / -사용)
  balance_after    BIGINT NOT NULL,
  idempotency_key  VARCHAR(100) NOT NULL UNIQUE,  -- 이중 반영 방지 핵심
  source           VARCHAR(30) NOT NULL,          -- EVENT, PAYMENT, ADMIN
  reference_id     VARCHAR(100),
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_ledger_user_created ON point.point_ledger (user_id, created_at DESC);
```

## 3. 반영 흐름 (Kafka consumer)

```
BEGIN;
  INSERT INTO point_ledger (... idempotency_key ...) ON CONFLICT (idempotency_key) DO NOTHING RETURNING id;
  -- 반환 행 없음 → 이미 처리됨 → COMMIT 후 offset 커밋
  UPDATE point_wallet SET balance = balance + :amount, version = version + 1 WHERE user_id = :uid;
COMMIT;
→ Kafka offset commit (수동)
```
- 실패 시 3회 재시도 → `point.reward.dlq` 로 이동 → 운영자 재처리
- 위 흐름은 출석 보상 등 **즉시 지급** 건. 퀴즈 당첨(`reason=QUIZ_REWARD`)은 아래 3.1 로 간다

### 3.1 퀴즈 당첨 일괄 정산 (ADR-0017)
```
[이벤트 중]  INSERT INTO reward_pending (idempotency_key, event_id, user_id, amount) ON CONFLICT DO NOTHING;
[종료 후]    POST /api/admin/events/{id}/settlement {"expectedCount": SCARD event:{id}:winners}
BEGIN;
  pg_advisory_xact_lock('settlement:'||id)                 -- 같은 이벤트 정산 직렬화
  count(reward_pending) ≠ expectedCount → 409 SETTLEMENT_NOT_READY (원장 미변경)
  SELECT ... FROM point_wallet WHERE user_id IN (당첨자) ORDER BY user_id FOR UPDATE;
  INSERT INTO point_ledger SELECT ... FROM reward_pending ... ON CONFLICT (idempotency_key) DO NOTHING RETURNING ...;
  UPDATE point_wallet SET balance = balance + amount ...;   -- 새로 들어간 건만
  INSERT INTO event_settlement (event_id, row_count, total_amount);
COMMIT;
```
- 이미 정산된 이벤트에 다시 호출하면 원장에 없는 대기 건만 채운다 (DR 재정산, 재실행 안전)

## 4. 대사(Reconciliation)

| 비교 대상 | 주기 | 불일치 처리 |
|---|---|---|
| Redis 당첨자 수 ↔ reward_pending 건수 (퀴즈) | 정산 시 (전제조건) | 다르면 정산 거부 → lag 해소 후 재시도 |
| event_settlement.row_count ↔ ledger 건수 (퀴즈) | 정산 직후, DR 승격 시 | 재정산 (멱등) |
| Redis 출석 비트맵 ↔ ledger(source=EVENT, reference_id=attendance-*) | 일 1회 | 누락분 재발행 |
| Σ ledger.amount ↔ wallet.balance (사용자별) | 일 1회 | 알람 + 수동 조사 |
| RDS ↔ Cloud SQL 행 수/체크섬 (CDC 대상 테이블) | 일 1회 | 복제 재동기화 |
